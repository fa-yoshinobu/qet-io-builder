# 開発・保守

[README](../README.md) / [使い方](使い方.md) / [設定ファイル](設定ファイル.md) / [図面の書き方ルール](図面の書き方ルール.md)

現在の構成と保守手順をまとめる。実施履歴・検証件数は [CHANGELOG](../CHANGELOG.md)、残件・未確認事項は [TODO](../TODO.md) を参照する。外部反映の状態はGitのログ・差分で確認する。

## 変更する場所

個々の生成QETを直すのではなく、生成処理・部品定義を修正する。図面の寸法・配置・注記・端子・NCの扱いは [共通ルール](図面の書き方ルール.md) に従う。

| 場所 | 役割 |
|---|---|
| `gen_io_page.py` | プロジェクト生成、PLC本体・構成・IO等の描画 |
| `renderers/` | 通信・GOT・リモート・アナログ・記入欄・共通コネクタ・標準部品等の描画 |
| `gui_web.py`, `webgui/`, `GUI起動.bat` | 画面（pywebview）。処理は `webgui/api.py`、表示は `webgui/static/`。変更反映には画面を再起動する |
| `gui_core.py` | 画面に依存しない部品一覧・表示項目の処理。旧画面 `gui.py`（tkinter）と共用 |
| `project_wiring/` | 任意配線情報のデータ検査・入力欄の定義 |
| `parts/` | 機種別定義・部品・対応一覧。1形名1 JSON、各フォルダの `gui_properties.toml` でGUI項目を定義 |
| `tools/` | 部品書出し、一覧再作成、サンプル生成、プレビュー、PDF調整、参照表更新 |
| `tests/` | 自動テスト |
| `docs/` | 操作・設定・保守・作図ルール、`research/` は機能別の調査記録 |
| `Sample_qet/` | 保存済みサンプルQET・再生成用JSON。PDFを同居させてもGitへ含めない |

`parts/` はPLC・HMI・制御部品・電源・ネットワーク・コネクタに分かれる。対応機種は [units_supported.csv](../units_supported.csv) と各フォルダの対応一覧を参照する。

### 機種・プロパティの追加

[機種定義の追加方法](../parts/plc/mitsubishi/README.md) と [部品ライブラリ](../parts/README.md) を参照する。資料で確認した端子番号・端子名・配線方法と、資料番号・章・ページを定義へ記録し、未確認事項は推測しない。GUIの表示項目は対象フォルダの `gui_properties.toml` で管理する。

```console
python tools/export_units_csv.py
```

対応一覧のCSVはExcel向けUTF-8 BOM付きで再作成する。CSV入力形式は [設定ファイル](設定ファイル.md) を参照する。

### 描画・入力検査の担当

- VT3・VT5・NA5も`unit_diagram`で定義し、タッチパネル本体は`renderers/touchpanels.py`で2列に配置する。長い端子展開は共通端子表へ送り、通信コネクタと実ピンの接続点を重複させない。

- キーエンスKV・オムロンNXの単体図は機種別JSONの`unit_diagram`と`renderers/unit_diagrams.py`で扱う。`sections`で端子台・コネクタ・独立COMの所属を保持し、明示された`lane`と`power_group`だけを自動給電する。通常I/Oの接続先はQETで記入・配線する。既存KVデジタル配線例は`kv_io`と`renderers/keyence.py`で扱う。

- アナログのNC所属・CH内の並び・接続ポイントなしの表示は `renderers/analog.py` で共通化し、NCも行数に含める。FX5アナログの右半ページ配置、GOT Ethernetの段間隔などの確定値は共通ルールを参照する。
- 出力の機器番号はプロジェクト全体で重複検査する。同じコイルを参照する入力接点には同じ番号を使える。デジタルIOの信号端子重複は定義読込み時に拒否する。
- Q CPUの仕様表示・装着品候補・増設上限・スロット検査は機種別定義に基づく。詳細は [Q CPUの選択仕様](research/q_cpu_selection.md)。
- 任意配線情報の追加表示と送り受けリンクは `renderers/wiring.py`、外部端子台の接続図は `renderers/terminal_plan.py`。設定と制約は [設定ファイル](設定ファイル.md) の「配線情報・端子台接続表」を参照する。
- a/b参照表は保存済みQETを `tools/update_xrefs.py` で更新する。操作・位置追従・バックアップの扱いは [使い方](使い方.md) の「a・b接点の参照表を更新する」を参照する。

## 検証

リポジトリのフォルダで実行する。

```console
python -m unittest discover -s tests
python gen_io_page.py project.json 出力.qet
python tools/preview_qet.py 図面.qet 出力フォルダ all
```

変更に応じたテストと代表図面を確認する。簡易PNGの配線は近似表示なので、最終確認はQETのPDFで行う。全機種の実画面・実機配線を確認済みとは扱わず、個別の確認状態は機種別定義・対応一覧を参照する。

生成範囲と外部反映はその時の依頼に従い、変更前QET・PDFの退避ファイルを一律には作らない。未作成機種という理由だけで残件を追加しない。検証の成功・失敗・修正後の再実行範囲はCHANGELOGへ、未確認の機能はTODOへ記録する。TODOには図面の見た目・レイアウトの確認や、図面を確認した履歴を記載しない。

## 資料・生成物

- ローカルの生成物は `pdf_*/`、確認用QET・PNG・検証記録は `_review/` に置く。メーカー資料・PDFとともにGit対象外とする。
- **参考用メーカー資料の本文・抜粋・要約はドキュメントへ転記しない。** 独自実装の操作方法・設定・作図ルールは、それぞれの文書へ記載する。
- JSON・MDの出典は資料名・文書番号・章・ページで記録し、PDF直リンク・個別のローカルパス・PDFファイル名・資料を保存した記録は記載しない。
- PDFはQET標準のエクスポート後にA3横・均等余白へ調整する。自動書出しは既存PDFを成功後だけ置換し、QETを一括終了しない。手順は [使い方](使い方.md) の「PDFとプレビュー」を参照する。

### サンプルとローカル出力

公開サンプルは `Sample_qet/`、案件ごとの生成物は指定した出力フォルダに保存します。ローカルの `pdf_*/` と `_review/` はGit対象外で、他のPCに存在することを前提にしません。掲載機種や確認範囲は各サンプルのJSONとCHANGELOGを参照してください。

### 保存済み図面を再生成する

分類別の図面は、各フォルダの `project.json` を `gen_io_page.py` に渡し、同じフォルダのグループ名と同名のQETへ出力する。入力CSV・構成を維持して最新の生成処理を反映する。

既存のハブ・電源サンプルは次のコマンドで再生成できる。

```console
python tools/regenerate_hub_power_samples.py
```

既存QETの掲載機種・配置・タグ・ページ情報を保持し、埋込み部品を現在の定義から更新する。成功後だけ出力を置き換え、失敗時は既存QETを保持する。`_review` 内の一時スクリプトを生成元として使わない。

全電源の部品確認QETは `python tools/make_power_sample.py 出力.qet` で生成する。小型枠6台、多端子・通信付き4台、分岐電源2台を各ページに配置する。PDFは同フォルダへQET標準エクスポートで出力する。

## 資料の記載

説明の詳しさは、操作・選定・誤配線防止・保守に役立つかで判断する。型式・件数・確認状態は対応一覧の表にまとめ、表の下に同じ確認状況や作業履歴を重ねない。本文は操作・仕様・適用条件を補う説明に使う。

対応一覧・説明資料には文書番号と照合ページを記載し、資料の入手先URLや取得・保存先の案内は書かない。Git除外方針は、この文書の保守手順にまとめる。

## 生産終了年の表示

機種別JSONの `definition.production_end_date` に公式の生産終了日（`YYYY-MM-DD`）、`production_end_source` に根拠の公式HTMLページを記録する。Web版の部品選択一覧は年だけを表示し、当日より後の終了日は「予定」を付ける。未登録は「—」とし、販売中とは断定しない。図面には自動転記しない。
