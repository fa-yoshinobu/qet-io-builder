# 設定ファイル

[READMEへ戻る](../README.md) · [使い方](使い方.md) · [開発・保守](開発・保守.md) · [図面の書き方ルール](図面の書き方ルール.md)

プロジェクトJSONと入出力CSVの項目を説明します。GUIの操作手順は[使い方](使い方.md)、図面の配置・表記は[図面の書き方ルール](図面の書き方ルール.md)を参照してください。

## プロジェクトJSON

日付・作成者・改訂・電源設定などの省略項目は生成時に補完します。日付の既定値は実行日です。既に指定した値は維持します。GUIの新規プロジェクトにも同じ既定値を入れます。

```json
{
  "project_title": "装置A 電気図面", "company": "", "customer": "", "machine": "装置A",
  "drawing_no": "E-0001", "revision": "A", "date": "20261028",
  "author": "", "checker": "", "approver": "",
  "power": {"P": "+24V", "N": "0V"},
  "front_pages": true,
  "pages": []
}
```

`pages` に、後述するページ設定を並べます。CSVなどの相対パスは、プロジェクトJSONの場所が基準です。

| 項目 | 内容 |
|---|---|
| `project_title` | プロジェクト名 |
| `company` / `customer` / `machine` | 会社・顧客・装置の情報 |
| `drawing_no` / `revision` / `date` | 図番・改訂・日付 |
| `author` / `checker` / `approver` | 作成者・検図者・承認者 |
| `power.P` / `power.N` | P/N電源の設定。上の例では `+24V` / `0V` |
| `power.P_name` / `power.N_name` | 電源レーンの名前。既定は `P24` / `N24` |
| `front_pages` | 表紙・改訂履歴・目次を付ける。既定は `true` |
| `revisions_csv` | 改訂履歴のCSV。列は `改訂,日付,変更内容,対象ページ,作成,承認` |
| `zone_col_start` | 区画の列番号の始まり。既定は `1`。QETの設定に合わせる |
| `relay_default` / `relay_types` | 区分参照に使うリレー形式。既定は `MY4N` |
| `units_dir` | 標準の `parts/` 以外の機種定義フォルダを使う場合に指定 |
| `pages` | 生成するページ設定の配列 |

CSVやJSONを直して再生成すると、QETで手直しした分は上書きされます。

## ページの種類

`pages` の各設定で `kind` を指定します。

| `kind` | 内容 | 例 |
|---|---|---|
| `terminal_block` | ケーブルで接続するPLCのI/O図と中継端子台図を別ページに生成 | `{"kind":"terminal_block","plc_model":"KV-NC32EX","plc_tag":"PLC1","model":"PCX-1H34-TB34-K1","tag":"XT1","cable":"GRPTS-M34-M34-1","cable_tag":"W1"}` |
| `input` / `output` | iQ-R・Q・リモートIOの入出力 | `{"kind":"input","model":"RX41C4","csv":"x.csv","start":"0","relay":"A6TBXY36","tb_name":"TB-X"}` |
| `qmixed` / `iqrmixed` / `remotemixed` | 入出力混合ユニット | `{"kind":"qmixed","model":"QH42P","input_csv":"i.csv","output_csv":"o.csv"}` |
| `fx5u` | FX5本体の入出力 | `{"kind":"fx5u","model":"FX5U-32MR/ES","input_csv":"i.csv","output_csv":"o.csv","input_mode":"sink","relay_com_to":"P"}` |
| `fx5ext` | FX5増設入出力 | `{"kind":"fx5ext","model":"FX5-16EYR/ES","y_start":"20","output_csv":"o.csv"}` |
| `fx5body` | FX5本体図。電源・センサ電源・アナログ・RS-485・Ethernet・拡張ボード | `{"kind":"fx5body","model":"FX5U-32MR/ES","battery":"装着","board_model":"FX5-485-BD"}` |
| `iqrbody` / `qbody` | iQ-R・Qのユニット構成 | `{"kind":"iqrbody","model":"R04CPU","power_model":"R61P","base_model":"R35B","modules":["RX41C4",""]}` |
| `fx5analog` / `iqranalog` / `qanalog` / `remoteanalog` | アナログ端子 | `{"kind":"iqranalog","model":"R60AD4","csv":"a.csv"}` |
| `qcomm` / `iqrcomm` / `fxcomm` | 通信ユニット。左右に1台ずつ配置 | `{"kind":"iqrcomm","left_model":"RJ71C24","right_model":"RJ71GN11-T2"}` |
| `remotebody` / `remoteiolink` | リモートIOの通信・電源、IO-Link | `{"kind":"remotebody","model":"NZ2GF2B1-16D"}` |
| `gotbody` / `gotoption` | GOT本体、GOT通信オプション | `{"kind":"gotbody","model":"GT2510-VTBD","ip":"192.168.1.10"}` |
| `power` | 電源回路。AC → ブレーカ → DC24V電源 → P24/N24 | `{"kind":"power","model":"FX5U-32MR/ES"}` |

`terminal_block` で分岐ケーブルを使うときは、CN2側を `tag`、CN3側を `tag2` に指定します。KV-C64XCはL側に `tag`・`cable_tag`・`cable`、H側に `tag2`・`cable_tag2`・`cable2` を指定します。`cable2` 省略時はL側と同じ形名を使います。

### ページごとの主な設定

iQ-RのNZ1BLCは `batteryless`（有・無・要確認）で指定します。対応CPUはR04以降と各ENCPUで、拡張SRAMの `memory_cassette: "有"` との同時指定はできません。

- アドレス: iQ-R・Qは `start`（16進）、FX5増設は `x_start` / `y_start`（8進）。CSVのアドレスと一致させてください。
- 16点ユニットは左半分に描きます。`"right": {…}` に別の16点ユニットを書くと、右半分に並べます。
- 構成ページの `modules` はスロット0からの並びです。空きは空文字にします。RnENCPUはネットワーク部がスロット0を使うため、スロット1から並べます。
- 増設ベースは `"extensions":[{"base_model":"R65B","power_model":"R61P","modules":[…]}]` で指定します。増設上限はCPUの機種定義に従います。空きスロットの点数は `empty_slot_points`（既定16）で指定します。
- 構成図のスロットはアドレス範囲の高さをそろえて表示します。詳細図への参照は、タグ指定時は形名とタグの両方で照合します。同じ形名を複数使う場合は、構成図の `module_tags` と詳細図のタグを一致させてください。
- 電池は `battery`（装着・非装着・要確認）と `battery_model`、メモリは `sd_card`・`memory_card`・`memory_cassette`（有・無・要確認）と各キーの末尾に `_model` を付けた型式で指定します。省略時は要確認として、推測しません。
- Q・iQ-Rのメモリ型式候補はCPUごとの定義から読み、非対応品は生成時にエラーとします。SD型式は自由入力も可能ですが、登録済み型式で当該CPUに非対応と確認したものは指定できません。図面には「有」の型式だけを表示します。候補・根拠は [CPUのオプションメモリ](research/cpu_memory_options.md) を参照してください。
- 通信・機器設定は `station` / `ip` / `communication` / `dip` を使います。機種に応じて候補と初期表示を決め、表示中の欄が空欄なら「（記入）」を出します。

通信・機器設定欄の機種別表示は [機種別の設定欄一覧](機種別の設定欄.md) を参照してください。`communication` は「通信設定」、既存の `dip` は「機器設定」です。左右のユニットには `left_` / `right_` を付けます。

`settings_visibility` で欄の表示を切り替えます。省略時は機種別の初期表示を使います。`false` でも入力値は保存し、再表示で復元します。非表示の欄は図面の枠も出力しません。

```json
{
  "right_ip": "192.168.1.10",
  "left_communication": "10 Mbps",
  "settings_visibility": {"right_ip": false, "left_communication": true}
}
```
- iQ-R低電圧入力（RX70C4など）は `input_voltage` に `5` または `12` を指定します。
- GOTの共用シリアルは `serial_mode`（RS-232 / RS-422/485）を指定します。GT25-FNADPは `left_module` / `right_module` に通信モジュール（ABCC-M40-DPV1 / ABCC-M40-DEV）を指定します。

CPUの増設上限・装着品の候補は機種定義に従います。Qの詳細は [Q CPUの選択仕様](research/q_cpu_selection.md) を参照してください。

## タグ名とスロット・ユニット番号

タグ名（管理番号）は、図面内で部品を識別する自由入力欄です。例は `PLC1`、`UNIT1`、`AVR1` です。形名・ページ名とは別に保存し、空欄なら表示しません。

| JSONキー | 対象 |
|---|---|
| `tag` | ページの対象機器 |
| `power_tag` / `base_tag` / `board_tag` | 電源・ベース・拡張ボード |
| `left_tag` / `right_tag` | 左右の単体接続図の対象機器 |
| `module_tags` | 構成ページの各ユニット。`modules` と同じ順番の文字列配列 |
| `module_starts` | 構成ページの各ユニットの先頭XY（16進）。`modules` と同じ順番の文字列配列で、空欄は自動。増設段は各段に書く。指定値は直さず、16点単位でない・重なり・点数超過・入出力ページとの不一致は警告を出す |
| `slot` / `unit_no` | スロット番号・ユニット番号 |
| `left_slot` / `left_unit_no` | 左側の単体接続図の番号 |
| `right_slot` / `right_unit_no` | 右側の単体接続図の番号 |

構成ページでは電源・ベース・拡張ボードにも個別のタグを指定できます。構成ページとIOなど別ページに同じ機器を描く場合は、同じタグ名を指定してください。

IO表・箱型の単体接続図は上部に「スロットNo.｜タグ名｜形名」をまとめます。スロットのない機器は「ユニットNo.」を使います。番号も自由入力です。ユニットの機能名は箱の内側の最上部、注意書きはページ最下部に表示します。

単体部品のタグ名はQETの部品プロパティの「ラベル」、番号は「補助情報1（auxiliary1）」で編集します。

見出しの寸法・余白、端子や文字の位置は[図面の書き方ルール](図面の書き方ルール.md)を参照してください。

資料で確認済みのNC端子も省略せず表示します。NC行には配線用の接続ポイントを付けず、接続しない端子であることを示します。

通信ユニットのコネクタにピン情報が定義されている場合は、コネクタの横に「ピンNo.・信号・用途」の表を表示します。定義済みのNCも表示し、コネクタの接続ポイントは増やしません。ピン情報がないコネクタは、絵と名称を表示します。

## CSV

### 文字コードとExcel

UTF-8（BOMあり・なし）とCP932（Excelの「CSV(コンマ区切り)」）を読み込めます。生成する一覧・雛形はExcel用のUTF-8 BOM付きです。

### 入出力CSV

入力の列:

```csv
アドレス,信号名,機器番号,接点,線番,備考
```

出力の列:

```csv
アドレス,信号名,機器番号,負荷,形式,線番,備考
```

- `csv`（混合ユニットは `input_csv`・`output_csv`）を省略すると、アドレスだけを入れた空欄の図面を作ります。
- 信号名は2段までです。「|」で改行を指定でき、指定がなければ欄の幅で自動改行します。
- 負荷が `PL` なら表示灯、それ以外はコイルを描きます。
- 出力の負荷がリレー類（RY・MC・CR・KM・R）で、同じ機器番号が入力の接点にある場合は、コイルと接点の区分参照（例: `5-C15`）を自動で付けます。

### アナログCSV

```csv
CH,用途,方式,機器番号
```

`方式`（電圧 / 電流）を書くと、相手機器・シールド・電流入力の短絡線を描きます。空欄なら端子だけを描きます。

## 配線情報・端子台接続表

GUIでページを選択して「配線情報」を開くと、案件ごとの境界・接続先・ケーブル情報を任意に追加できます。機種定義や通常の用途欄とは別に、ページの `wiring` に保存します。未設定なら従来の図面・出力のままです。

### 境界と接続

- 「境界」は細い破線と左右の表記で、盤内／盤外などを区別します。
- 「接続」には、機器タグ・機器端子、端子台名・端子番号、線番、相手機器・端子、送り先、ケーブル番号・芯番号・線径・シールド・渡りを記入します。
- 接続先は推測しません。既存のIO CSVとは別の明示登録なので、同じ端子や線番を登録する場合は一致させてください。
- 配置タブで分割ページと位置を指定します。分割ページは、そのページ設定から生成される本文の1枚目を1とし、表紙・目次は数えません。
- 追加した注記はQETで移動・編集できます。既存の機器やIO表は移動しません。注記は空き領域へ置き、配線や文字と重ねないようにしてください。
- 通信ページに機器が1台だけある場合、空欄の対象機器タグはその機器のタグを引き継ぎます。左右に2台ある場合は、接続ごとに対象機器タグを入力してください。

### 送り・受け

送り先を文字で記入する場合は「送り先」を使います。別のページにあるQET標準の送り・受け記号を対応させる場合は、2件の接続に同じ「参照ID」と、それぞれ「送り」「受け」を指定します。実際の相手ページ・位置はQETの参照表示を使います。

記号から機器端子への導体は、QETで接続してください。

### 端子段と端子台接続図

端子台名と端子番号を入力した接続がある場合だけ、図面生成時に `出力名_terminals.csv` を追加します。両側の接続先やケーブル情報を、端子台・端子番号の自然順で出力します。Excel用のUTF-8 BOM付きです。

「端子段」で上段・下段などを区別できます。「端子台接続図を追加」を選ぶと、登録した外部端子台の接続を本文末尾の表にも出力します。機器端子・線番・相手先・ケーブル・芯番号を別列にし、長文と複数ページに対応します。JSONでは `wiring.terminal_plan: true` と、接続行の `level` を使います。

### JSON例

ページ設定の `wiring` の最小例です。1枚目の空き領域に接続注記を配置します。

```json
{
  "wiring": {
    "boundaries": [{"x": 800, "top": 75, "bottom": 750, "left": "盤内", "right": "盤外"}],
    "connections": [{
      "part": 1, "x": 900, "y": 110,
      "unit_tag": "PLC1", "unit_terminal": "X0",
      "terminal_block": "TB1", "terminal": "1", "wire": "101",
      "peer_tag": "LS1", "peer_terminal": "13", "destination": "5-B3",
      "cable": "W1", "core": "3", "section": "0.75"
    }]
  }
}
```

入力フォームの保存内容から図面と接続表を生成します。生成後にQETで変更した注記や配線を、プロジェクトJSON・CSVへ逆反映する機能はありません。

## CC-Linkパルス・MXコントローラ

| kind | 内容 | 機種定義 |
|---|---|---|
| `remotepulse` | 高速カウンタ・位置決めの信号端子 | `remote_pulse` |
| `mxbody` | MX-F本体の電源・通信・USB・装着品 | `mx_cpu` |
| `mxio` | MX-F本体または専用IOの信号端子 | `mx_cpu` / `mx_io` |
| `iqrbody` | MX-R構成図。電源・ベース・modulesはRシリーズを使用 | `iqr_cpu`（mx_rフォルダ） |

`mxio`の`x_start` / `y_start`は16進数です。`remotepulse` / `mxio`の任意CSVは `No.,端子,信号,用途` の形式で、`No.`によって用途を対応付けます。同じコモン端子名が複数あっても各実端子を別行で保持します。

定義に端子番号がない製品は番号を推測で補いません。AJ65BT-D75P2-S3の`AX1:1`等は「軸1の実ピン1」を表す図面上の識別表記です。

## インバータ

`kind: "inverter"`、`model`に対応形名を指定します。機種別定義は`parts/inverter/mitsubishi/e800/body`と`d800/body`。`tag`・`unit_no`・`title`を指定でき、設定欄の表示は既存の`settings_visibility`で切り替えます。

定義の`terminal_groups.left/right`が用途別の実端子（記号と短い用途）、`ports`が通信・USBコネクタです。同じ記号を持つ別端子も省略しません。単相品のT/L3、単相100V品のP1は定義に含めません。D800のR+/FU・R-/SDは切換式の同一端子として1行ずつ描きます。`PE`は図中では接地記号で表示します。

### MX-Fの機種情報・増設

`mx_cpu`と`mx_io`に入力電圧、出力形式・外部電源、端子台種別、資料番号を保持します。本体の`fixed_io_start`はtrueで、内蔵I/Oの0000H固定を検証します。端子記号は`signal_terminals`の値、アドレスは`x_start`/`y_start`による割付値です。

`mxbody.modules`に選択形名を配列で指定し、`module_tags`に同じ順でタグを指定します。選択範囲はCPU定義の`compatible_modules`。MX-F専用IOとFX5拡張アダプタを描画し、増設入力・出力は各0010Hから個別に割り付けます。ネットワーク機能部0400H、モーション機能部0420Hは本体の内蔵機能です。

根拠：SH-082633-E 冊子53～56、192～199、208～211、272～275、282～284ページ。EtherCAT仕様はSH-082745-A 冊子11、19～21、50ページ。
